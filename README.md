# 本部タスク（ネコロボマン本部のタスク管理）

Google ToDo リストと同じ操作感のタスク管理アプリと、Google カレンダーと同じ操作感のカレンダーです（画面上の「タスク ／ カレンダー」で切り替え）。タスクには次の機能を足しています。

- **誰が・いつまでに・何を** の3つを入れないと登録できない（繰り返しのタスクは期限なしも選べる）
- **いつやる**（取りかかる日）も、期限とは別に決められる
- **ほかの人にタスクを頼む・ほかの人のタスクを見る**: 左の「メンバー」から
- **繰り返し**: Google ToDo リストと同じ設定（毎週○曜日・毎月第○○曜日・終了日や回数など）
- **進捗管理**: ステータス（未着手・進行中・完了）、最新状況の入力（日時・名前つきで残る）、進捗ボード
- **毎時のメール通知**: 平日 10:00〜17:00 の毎時ちょうどに本部全体の状況を送り、17:30 に「今日のまとめ」を送る（時刻は画面で変えられる）
- **同じアカウントを何人かで同時に使っても大丈夫**: ほかの人の変更が、その瞬間に全員の画面に出る
- **アカウントは招待制**: 管理者が管理画面（`admin.html`）から招待した人だけが使える。招待されていないアドレスではアカウントを作れない（詳しくは [アカウントと管理画面](docs/accounts.md)）
- **Google 連携**: 一人ずつ自分の Google アカウントをつなぐと、担当のタスクが Google ToDo リストに、自分の予定とゲストに呼ばれた予定が Google カレンダーに自動で出る（アプリ → Google の一方向）
- **全権限のアカウント**: 本部の管理用アカウント（ネコロボマン本部）は全権限。ほかの管理者が止めたり外したりできない
- **カレンダー**: 日・週・月・年・スケジュール表示、ドラッグで作成・移動、繰り返し、ゲストと出欠、通知、共有のカレンダー。タスクと祝日も重ねて表示（Meet はなし。詳しくは [カレンダー要件定義書](docs/calendar.md)）

**本番の URL: https://app.nekorobogroup.com/honbu-task/** （Xserver。中身はこのリポジトリの `web/` と同じ）／ **管理画面: https://app.nekorobogroup.com/honbu-task/admin.html**（管理者だけ）
（前のアドレス https://app.nekorobogroup.com/ を開いても、自動で新しいアドレスに移ります）

| 置き場所 | 中身 |
|---|---|
| 画面 | Xserver（app.nekorobogroup.com の `honbu-task` フォルダ）。`web/` の中身をそのまま置く |
| データ・ログイン・リアルタイム通知 | Supabase（東京）。組織「株式会社ネコロボマン」のプロジェクト「nekorobo.app」 |
| メール送信 | 共有 Gmail から送る小さな GAS（`gas-relay/`） |

設計の理由は [構成の設計](docs/architecture.md)、機能の一覧は [要件定義書](docs/requirements.md) と [カレンダー要件定義書](docs/calendar.md) にあります。

## 使い始めるまで

### 1. 画面を置く（Xserver）

`web/` の中身を、app.nekorobogroup.com の公開フォルダの中の **`honbu-task` フォルダ**にそのまま置く（フォルダの形もそのまま）。更新のときは、変わったファイルだけ上書きする。
公開フォルダの一番上には `web-root/` の中身（前のアドレスから新しいアドレスへ移す小さなページと robots.txt）を置く。ほかのアプリを一番上に置くときは、これを入れ替える。

### 2. 管理者がログインする

1. 最初の1回だけ: 渡された招待のリンクを開き、本部の共有アカウント（最初の管理者）のパスワードを決める
2. https://app.nekorobogroup.com/honbu-task/ を開き、そのメールアドレスとパスワードでログインする
3. 共有のアカウントでは「操作する人を選んでください」と出るので、自分の名前を選ぶ（いなければ名前を入れて「追加して選ぶ」）
   - 何人かで使うアカウントなので、**誰が操作したかを記録するために**端末ごとに名前を選びます

### 3. 本部の人を招待する（管理画面）

1. https://app.nekorobogroup.com/honbu-task/admin.html を開き、もう一度ログインする（管理画面は、アプリとは別にログインが要ります）
2. 「アカウントを招待する」に名前とメールアドレスを入れて「招待する」
   - 本人に、パスワードを決めるリンクがメールで届く（7日間・1回だけ使える）。メール送信用の GAS が動いていないときは、画面に出るリンクをコピーして本人に届ける
3. 本人がリンクを開いてパスワードを決めると「使用中」になり、次からはそのメールアドレスとパスワードでログインする
   - 本人のアカウントでは、登録・変更の記録に本人の名前が自動で残る（操作する人を選ぶ必要はない）
4. パスワードを忘れた人には「パスワード再設定」、やめた人は「停止」。管理者を増やすときは「管理者にする」
5. 歯車 →「メール通知」で、送信先のアドレスを入れて「1時間に1回…送る」をオンにして「保存」（管理者だけ）

### 4. メール送信用の GAS を置く（共有アカウントで）

1. Google ドライブの「本部タスク メール送信用GAS（貼り付け用）」を開き、中身を全部コピーする（合言葉が入った状態で用意してあります）
2. https://script.google.com で「新しいプロジェクト」を作り、「コード.gs」の中身を全部消して貼り付け、保存
3. 関数の選びボックスで **`setup`** を選んで「実行」→「権限を確認」→ 共有アカウント →「詳細」→「（安全ではないページ）に移動」→「許可」
4. 本部タスクの歯車 →「メール通知」に「メール送信用の GAS は動いています」と出れば OK。「保存してテスト送信」で、1分以内にメールが届くか確認する

### 5. Google 連携（ToDo リスト・カレンダー）

1. **管理者が1回だけ**: 管理画面の「Google 連携」を開き、書いてある手順で Google Cloud の設定をする（本部の Google アカウントで。プロジェクトを作る → Tasks API と Calendar API を有効にする → OAuth 同意画面を「本番環境」にする → OAuth クライアント ID を作る）。画面に出る「承認済みのリダイレクト URI」をそのまま Google に登録し、できた「クライアント ID」と「クライアント シークレット」を管理画面に貼って「保存」（チャットやメールには貼らない）
2. **一人ずつ**: アプリの歯車 →「Google 連携」→「Google と連携する」→ 自分の Google アカウントを選び、ToDo リストとカレンダーの両方にチェックを入れて「続行」
   - 「Google はこのアプリを確認していません」と出たら「詳細」→「（安全ではないページ）に移動」で進む（本部だけで使うため、Google の審査は受けていない）
3. 1分ほどで、担当のタスクが Google ToDo リストの「本部タスク」に、自分の予定とゲストに呼ばれた予定が Google カレンダーに出る。そのあとも、変わったものが1分ごとに反映される
   - アプリ → Google の一方向。Google 側で変えても、アプリには戻らない
   - Google 連携は一人ずつのアカウント（個人のアカウント）で使える。共有のアカウントでは使えない

## 使い方のポイント

| やりたいこと | 操作 |
|---|---|
| タスクを登録 | リストの「タスクを追加」か、左上の「作成」。タイトル・期限・担当者を選んで Enter（「いつやる」は任意） |
| ほかの人に頼む | 左の「メンバー」でその人を開き、「○○さんにタスクを送る」→ 入れて「タスクを送る」。担当者にその人を選んで登録しても同じ。送るとすぐ相手の画面に出て、知らせも出る |
| 頼んだタスクを消す | 消せるのは、頼んだ人と管理者だけ（頼まれた人は、完了・最新状況・期限の変更はできるが、消せない） |
| ほかの人のタスクを見る | 左の「メンバー」でその人を開く。その人のタスクが、リストごとのカードに分かれて出る。「依頼したタスク」で、その人が頼んだものも見られる |
| 繰り返す | 追加欄の「繰り返し」か、タスクの詳細の「繰り返し」。「毎月 第3水曜日」「毎月 最終金曜日」「2週間ごと」「毎年」などは「カスタム…」（間隔・曜日・日にちか第何曜日・開始日・期限・終了） |
| 進み具合を書く | タスクを開いて「最新状況」に書いて「記録する」。未着手なら自動で「進行中」になる |
| 完了にする | 丸いチェックを押す。下の「元に戻す」で取り消せる |
| 期限を延ばす | タスクを開いて期限を変える。理由を残す欄が出る（任意） |
| 全体の状況を見る | 左の「進捗ボード」 |
| 自分の分だけ見る | 左の「自分の担当」 |
| 消したタスクを戻す | 左の「ごみ箱」（30日間戻せる） |
| 予定を入れる | 画面上で「カレンダー」に切り替え、空いている時間をクリック（ドラッグで長さを決める）。出てきた小さな画面で日付・時刻を変えられ、枠をドラッグしてずらすこともできる。詳しく入れるときは「その他のオプション」 |
| 予定をずらす・長さを変える | 予定をドラッグして別の時間・日へ。下の端を引っぱると長さが変わる（Google カレンダーと同じ） |
| 予定に人を呼ぶ | 予定の編集画面の右「ゲストを追加」。呼ばれた人のカレンダーに出て、「はい・いいえ・未定」を返せる |
| ほかの人の予定を見る | カレンダーの左「他のカレンダー」でその人にチェック |
| スマホの Google アプリで見る | 歯車 →「Google 連携」で自分の Google をつなぐ（上の「5. Google 連携」） |

- タスク名や最新状況に、**利用者さんの名前などの個人情報は書かないでください**（メールで社外のサーバーを通るため）
- Gmail の無料アカウントは、メールを1日100通（宛先の数で数えます）まで送れます。最初の設定（1日9回）なら、宛先は11件までにしてください

## よくある困りごと

| 困りごと | 直し方 |
|---|---|
| ログインできない | メールアドレスとパスワードを確認。パスワードを忘れたら、管理者に管理画面の「パスワード再設定」でリンクを作ってもらう |
| 「このアカウントは使えません」と出る | 招待されていない、または停止されたアカウント。管理者に確認する |
| 招待のリンクが使えない | 期限切れ（7日）・使用済み・作り直し済み。管理者に「招待を送り直す」を頼む |
| メールが届かない | 歯車 →「メール通知」を見る。「メール送信用の GAS が動いていない」と出たら、手順4をやり直す |
| 画面が古いまま | 自動で最新になります。右上が「オフライン」のときは通信を確認 |

## データを取り出す（CSV）

データはすべて Supabase（プロジェクト「nekorobo.app」）の表に入っています。表ごとに CSV で取り出せます。

1. Supabase の管理画面（https://supabase.com/dashboard）にログインし、「nekorobo.app」を開く
2. 左の「Table Editor」で表を選ぶ
3. 表の名前の横の「…」→「Export data」→ CSV を選ぶ

| 表 | 中身 |
|---|---|
| `tasks` | タスク（担当者・期限・いつやる・状態など。消したものは `deleted_at` に日時が入る） |
| `task_notes` | 最新状況 |
| `task_history` | 変更の記録（誰が・いつ・何を変えたか） |
| `lists` | リスト |
| `members` | メンバー（ほかの表の担当者・作った人などは、この表の `id`） |
| `calendars` ・ `events` | カレンダーと予定 |

- Excel で文字化けするときは、Excel の「データ」→「テキストまたは CSV から」で開く（文字コードは UTF-8）
- 画面やプログラムは、このリポジトリ（GitHub）にすべて保存されている

## 開発者向け

```
web/            … 画面（Xserver の app.nekorobogroup.com/honbu-task/ に置く）
  app.js          画面の動き（Preact）。データは Supabase の api_call（入り口）から api_* 関数で読み書きする
  admin.html/js/css 管理画面（管理者だけ。アカウントの招待・停止・パスワード再設定）
  calendar.js     カレンダーの画面（app.js の部品を受け取って動く）
  calendar.css    カレンダーの見た目
  styles.css      見た目
  config.js       つなぎ先（公開してよいキーだけ）
  vendor/         画面の部品（Supabase JS・htm/Preact・Material アイコン。同梱）
web-root/       … app.nekorobogroup.com の一番上に置く（前のアドレスから /honbu-task/ へ移すページ・robots.txt）
supabase/
  migrations/     データベース（表・守り・api_* 関数・リアルタイム通知）
  functions/
    mail/           毎時メールの中身を作る（送信用 GAS とプレビューから呼ばれる。中身の作り方は report.ts）
    account/        招待・パスワード再設定のリンクを開いた人が、パスワードを決める
    account-setup/  以前の「はじめての方」の入り口（招待制になったため使えない）
    google/         Google 連携（Google の許可・トークンの保存・1分ごとの反映。何をどう送るかは plan.ts）
gas-relay/      … メール送信用の小さな GAS（合言葉は入っていない。貼り付け用はドライブにある）
gas/ dist/      … 旧版（スプレッドシート版）。使わない
dev/            … 動作確認用（試験用サーバー・テスト）
docs/           … 要件定義書・構成の設計・メールの見本
```

```bash
(cd dev && npm install)           # 手元で PostgreSQL（PGlite）を動かす部品を入れる（最初だけ）
node dev/db-test.js               # データベースのテスト（supabase/migrations をそのまま手元で動かす）
node dev/google-test.js           # Google 連携で「何をどう送るか」のテスト（Google にはつながない）
node dev/web-server.js 8095       # 画面の試験用サーバー（本番と同じ SQL を手元の PGlite で動かす。本番には接続しない）
WEB=1 BASE=http://localhost:8095/ node dev/e2e.js   # 画面のテスト（ログイン・2人同時操作・依頼・繰り返し・カレンダー・招待と管理画面を含む。要 Playwright）
node dev/mail-sample.js           # メールの見本（架空のデータ）を docs/mail-sample.html に作る
node dev/test-server.js           # 旧版（GAS）のサーバー側テスト
```
